# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

## Durable design decisions

- The canonical visual contract is `../codex-usage-gpt-5.6-sol-xhigh-2/web-ui-design`: its screens, component crops, tokens, notes, and app icon take precedence over incidental details in the older revamp implementation.
- Keep the outer product calm: Overview, Sessions, Stats, and Settings should read like a compact local ledger, not an observability console. Do not add an “explain this total” surface or expose ingestion/replay accounting states in the primary UI.
- Preserve the useful session model through progressive disclosure. Session detail uses Summary and Activity: Summary is a quiet synopsis; Activity expands turns and agent branches inline to show authored/captured text, reasoning summaries, tool metadata, subagents, goals/plans, compaction, and final answers. Tool inputs/outputs and attachment/image payloads are neither part of the frontend contract nor rendered. Do not expose raw by-agent or by-turn accounting tables as a separate Usage tab.
- Keep agent detail in Activity; do not add a sampled agents card to the Summary sidebar.
- Models & Reasoning on Summary is the useful model-usage surface. Show model, reasoning effort, cost, API tokens, and share there, plus the compact share bar. Keep deeper usage attribution in the data/API layer rather than making the user scan raw accounting dumps.
- Activity is a reverse-chronological conversation ledger, anchored by meaningful root user requests rather than internal turns. Each collapsed exchange is exactly two reading lines: the request first and the latest assistant result second. Their order already communicates who said what, so sender icons belong only to individual communication rows inside an expanded exchange. Do not add a latest badge or model/count metadata strip to the exchange row; exceptional running or interrupted state may sit inline with the request. Duration is the root exchange wall clock, while Cost and API Tokens include the root plus every uniquely attributed Agent and Automated Review descendant displayed beneath it. The immediate child rows must reconcile exactly to the exchange total. Group subtotals remain visible when expanded; nested rows explain that subtotal rather than acting as additional peers. Day dividers remain timestamp-based full-day totals aligned with the same columns.
- Expanded exchanges remain reverse chronological so the latest result is immediately visible; they preserve the complete event record through hierarchy rather than deletion. User messages, assistant updates, assistant messages, and final answers show the message excerpt itself as the primary two-line row, without repeating meta labels such as “Assistant update”; compact sender icons distinguish only the individual communication rows inside an expanded exchange. Consecutive tool, reasoning, review, system, and subagent plumbing folds into quieter Work, Agent, and Automated Review groups that remain named and expandable, including a one-event Work group instead of leaking a lone internal call into the conversation. Context compaction remains visible as a quiet system milestone. Groups expand locally when their children are already present. Attribute a recorded model-usage fact only to an eligible assistant/model-produced event in the same turn and within two source records before its accounting snapshot; aggregate those facts into Work groups, never assign them to user/system/meta rows, and leave genuinely unattributed metrics as em dashes rather than `$0.00` or `0`.
- Activity type size is intentionally readable without making the ledger uniformly bold. Use 500 for collapsed exchange requests and their aggregate metrics, 400 for individual communication, time, cost, token, Work, Agent, Review, and system-detail rows, and 600 only for day labels, small statuses, and explicit Markdown emphasis. Keep the existing sizes when tuning this hierarchy.
- Activity durations stay precise at human scale: below one hour use minutes and seconds; at one hour or longer use hours and minutes. Apply the same formatter to day, exchange, group, and event rows.
- Expanded assistant communication is a reading surface, not a larger excerpt. Preserve Markdown paragraphs, ordered and unordered lists, restrained headings, blockquotes, safe links, and fenced code blocks there; keep collapsed exchange and communication rows compact and single-purpose.
- Expanded user communication leads with the full user-authored request as its reading surface. Captured app/browser state, response-annotation envelopes, and accessibility dumps remain available as quiet, collapsed textual supporting material; never let those transport envelopes dominate or repeat the request. Attachment and image payloads are intentionally omitted.
- The session ID in the detail header links to `codex://threads/{session_id}`. Codex is the full-fidelity inspection surface for raw tool payloads and attachments; the dashboard remains a compact analytical projection.
- When one exchange crosses a local midnight, its expanded timeline gets quiet inset date labels. Do not add another colored rail: the outer day divider remains the only rail in Activity.
- In Activity, the colored left rail belongs only to the day divider. Expanded exchanges use one quiet inset surface and horizontal separators; do not add per-turn, per-tool, per-agent, or nested-detail rails. Keep model and reasoning effort on the execution detail where it adds meaning, not on the collapsed exchange; omit rollout/agent IDs, and render Markdown as readable content rather than leaking syntax or destinations into row excerpts.
- Expanded Work, Agent, and Automated Review groups keep a cool blue-gray header while their revealed child rows sit on a much lighter neutral-gray surface (`#f7f7f5`). Preserve that parent/child color distinction and direction: the children are lighter than the parent, never darker.
- Activity expand/collapse chevrons occupy the dedicated Details column at every nesting depth and never overlap Duration, Cost, or API Tokens. Keep each chevron's right inset coupled to the row's right padding when nested geometry changes.
- Settings contains only Price Data. Unknown prices appear as a restrained warning. Price and alias edits are explicit and apply retroactively through backend query-time pricing.
- Desktop at 1440px is the fidelity target. Smaller desktop widths may horizontally scroll dense ledgers rather than collapsing or hiding data.
- Use one 32 px page gutter for primary ledgers. On Sessions, the search, filters, result banner, session header/rows, empty state, and pagination share the same left and right edges; do not add a second inset inside the ledger. On session Activity, the column header, day bands, event rows, empty state, and pagination use that same gutter. Stats uses the same 32 px gutter as its controls and 13 px body rows to match Sessions; show the current and past periods, including empty past periods, but suppress future periods as visual noise.
- On Sessions, keep Last Activity and Cost legible as separate sortable controls with one quiet blue-gray separator at their shared header boundary. The separator is header-only and must not extend through session rows or alter column geometry.
- Stats period controls may switch immediately, but the ledger beneath them must never retain rows from the previous range or anchor. Show the correctly aligned ledger loading state until the matching response arrives, and cache each range/anchor independently so revisiting a loaded period is immediate.
- Stats period tabs use fixed one-pixel separators with both outer edges present when inactive. The selected tab is identified only by yellow fill and an inset 8 px coral marker; make its adjacent separators transparent without changing border widths so selection never produces black lines or horizontal jumping.
- Fira Sans 400/500/600 and the exported app icon are required assets. Preserve square corners, strong ledger rules, coral/blue section bars, yellow selection, and the supplied density.
